# AGENTS.md — Rudy Dres rd4: project context

Read this before touching the repo. Companion files: [FEATURES.md](FEATURES.md) (feature/progress tracker) and [PLAN.md](PLAN.md) (phased implementation plan — the workable plan to implement against).

## What this game is

A simple browser-based "karate" game — a beat-'em-up in the style of Amiga titles like *Renegade* or *Final Fight* — launched in a web browser (no installation) and played on **desktop with a keyboard**. The only playable character is **Rudy** ("rudy dres" = a red tracksuit guy), on a **real street in the owner's city** (Polish names: `01-narutowicza`, "Zielona 3", "Narutowicza 6"): fight enemies, complete missions, fight bosses. The two pillars are **combat and questing**. Tone: gritty Polish street humor. Player-facing names and error messages are Polish.

## Game world model

- The world consists of **streets**, each street made up of **sections**. The streets are played **one after another, in file-name order** (`01-narutowicza`, then `02-…`, `03-…`); the game ends when the **last** street is finished. A street is a single JSON file: `data/streets/<number>-<name>.json`.
- A street's **sections are placed from left to right** and can be traversed back and forth — the player walks into the neighbouring section and may return. There is **no route** any more: the section list in the config *is* the street.
- **No continuous scrolling**: each section is a **static background screen** (side-view street imagery with a flat street/sidewalk strip at the bottom where characters move); the game switches screens when the player reaches a section edge (like the Atari game *Ninja*). At the **ends of the street the boundary blocks Rudy and he walks in place**.
- **On entering a section** (the `Section.enter()` pipeline):
  1. load image → 2. set boundaries → 3. generate enemies → 4. apply the section trigger (the mission may move on) → 5. check the boss (mission gate) → 6. load the interactions.
- **On exiting a section**: **living** enemies → reset. **Defeated enemies persist as corpses** (with where they fell) in the global `State` — re-entering the section still shows the body instead of a fresh enemy. The mission, inventory, money, world flags and stats → do not reset (they live in the global `State`). There is **no save system** (session-only play): Rudy's defeat — like winning the game — shows a shared end screen with statistics and a restart button (click or Enter — Space does not restart; `game-over` on defeat / `<street>-congratulations` on victory, each played once — no loop; owner decisions 2026-10-11 to 2026-10-15; supersedes the earlier "save in the browser" expectation).
- This deliberately sets up moments like *"Oh, I came back here and things are different now."* — what spawns in a section can depend on the **mission stage** (see the boss `mission` gate in the street JSON).
- **Missions**: every street has **one main mission** — the `mission` field of the street config, an array of log lines where the index is the mission stage. The stage moves on through the transition maps in the config (section and interaction triggers). The HUD shows the street's opening objective on the first log row and the current objective on the second one. Side quests per section are still planned.
- **Bosses**: each section can have its own boss — it exists only on the mission stages listed in its `mission` field, and its `trigger` decides when the fight starts.
- Section backgrounds are loaded from PNGs named `<street>-<section>.png` (e.g. `01-narutowicza-1.png`) — real **photographs** of that part of the actual street, supplied by the owner.

## Tech stack

- Vanilla JavaScript ES modules, Canvas 2D. **No build step, no framework, no tests, no lint.**
- Run via any static file server from the repo root (the game `fetch`es JSON, so `file://` won't work). Open `index.html`.
- Canvas is fixed 1600x800, centered on a black page.
- All page and Canvas text uses the bundled root `PressStart2P-Regular.ttf` as **Press Start 2P**. `index.html` declares the face; `main.js` waits for it before starting the game. End-screen text sizes are fitted to the pixel font.

## Conventions (follow these, don't invent new ones)

- **Sprite sheets**: 150x150 px frames ("initially, all frames are 150x150px"), one animation per row. Row 0 = walk (8 frames). **Each move/attack = its own row of 4 frames**. Walk 80 ms/frame, punch 17.5 ms/frame. `facing = -1` mirrors horizontally. A sheet may also carry a **death row** (`deathRow` + `deathFrames` in the character config, default 4 frames) played on defeat while the body slides a little back (opposite the facing) — e.g. `lysy-blokers` row 2 (4 frames), `zul-mietek` row 2 (4 frames), **Rudy's `rudy_dres` row 2 uses all 8 frames** (owner 2026-10-15). The end screen waits for the fall to finish before freezing the scene. Sheets without a death row fall back to a rotated placeholder pose.
- **Moves are data-configured**: a character's config maps input keys → sprite rows (`{ key, row, type: punch|kick|headbutt|vomit }`), never hardcoded per character (`data/characters/*.json`, loaded via `character-defs.js`). A move with `"alternate": true` switches between the row's two 4-frame groups on **every other attack** (e.g. Rudy's punch: frames 0–3 right hand, 4–7 left hand); without it the animation is always the same. The boss's combined ranged move is explicitly `type: vomit`, excluded from melee RPS.
- **Combat is universal**: the same combat logic serves Rudy, standard NPCs and bosses — they differ only in their parameters (stats, attack set).
- **Combat timing** (P1.1/P1.2, verified 2026-10-18): hits resolve at **full extension**, in finish-time order. Already-started opposing melee attacks finishing within **100 ms inclusive** use headbutt > punch > kick > headbutt, without delaying single strikes; a later winner still must finish and reach its target. Equal move types favor the earlier finish; identical finish times draw. Jump/retreat can interrupt Rudy's windup immediately; an airborne target dodges melee/vomit, while retreat must actually leave reach. Evasions are not buffered and cannot undo damage already taken. **The retreat was removed on 2026-10-19** (↓ does nothing now) — the jump is the only evasion. **1 damage per hit**, interrupting the defender's blow; recovery is per character (`recoveryMs`, default 700 ms). **Rudy has none — every Space press queues a punch**. Enemies hold full stretch (`attackHoldMs`, default 150 ms; `lysy-blokers` 500 ms, `attackFrameMs: 75`).
- **Hit knockback** (P1.5): landed melee hits move their target away from the source by `HIT_KNOCKBACK_PX`, clipped flush to solids/street-end walls. **Ranged attacks such as vomit do not apply knockback or use this constant** (owner 2026-10-18). Misses and RPS draws do not push; lethal melee hits persist the displaced corpse position. The existing death-animation slide is separate.
- **No XP, no leveling**: progression and items are tied to missions; each mission gives a slight stat boost.
- **Audio layering**: street ambient → section music (overrides ambient) → boss music (overrides section music). The highest active layer wins.
- **Audio by convention** (`src/audio/audio.js`, files in `assets/sounds/`): `player-attack-miss`/`player-attack-hit` and `<enemyName>-attack-miss`/`<enemyName>-attack-hit` on attacks; `<who>-jump` (e.g. `player-jump`) when jumping; `<street>-<section>-ambient` loops per section (e.g. `01-narutowicza-1-ambient`), falling back to the default street ambience `ambience.mp3` (owner 2026-10-14 — the street is never silent during regular play). The ambience starts **automatically at boot** (owner 2026-10-15): plain `play()`, then a muted start that unmutes once running (browsers block audible playback before the first gesture), then the first key press/click as the last resort; `<street>-boss-music` loops during the boss fight while the boss's introduction sentence `<street>-boss-intro` plays once **on top of** it; `<street>-<interaction>-<trigger>` is the sound of an interaction (e.g. `01-narutowicza-sklep-0`); `game-over` plays ONCE on defeat and `<street>-congratulations` (e.g. `01-narutowicza-congratulations`) ONCE on victory — no loops, the end screen then stays silent (owner 2026-10-14/15). **Every convention file is optional — a missing file means silence.**
- **Art and audio are produced by the owner**: frame-by-frame 2D sprites (following the sprite-sheet convention), sound effects and music. Code selects assets by naming convention only and must never depend on specific asset content.
- **Hitbox**: feet area of the 150x150 frame, defined per character config (conventionally `{ x: 55, y: 120, w: 40, h: 25 }` — narrowed from 50 wide on 2026-10-13; combat measures hitbox-edge to hitbox-edge, see `combat.js`).
- **Blood VFX** (`src/render/blood.js`, owner 2026-10-14): every landed blow sprays 3x3 px red squares out of the struck character (player and enemies alike); they fly away from the blow, arc down and land on the ground line (the struck character's feet), staining it until the section is left — transient, like the enemies. An attacker can switch bleeding OFF (`"bloodOnTarget": false` in its character config): `zul-mietek` never makes the player bleed (owner 2026-10-15) — the player still bleeds zul with every landed punch.
- **Boss ranged attack** (`src/render/vomit.js`, owner 2026-10-15): ONE combined attack — the boss plays its attack animation and at full extension a burst of green vomit (5x5 px squares, 40 per burst, **twice as slow** since 2026-10-15) flies out; there is no separate melee blow. The burst hurts the player (1 damage) within about **300 px** of the mouth and the squares land on the ground at about **600 px** (both doubled by the owner on 2026-10-15), staining it until the section is left. Vomit never draws blood — the green squares are the whole effect. **Jumping over the spray dodges it** (owner 2026-10-15): a player in the air is not hit.
- **Delta time is milliseconds** throughout.
- **Persistent vs transient**: the mission/flags/inventory/money/stats live in the global `State` and survive section changes (the mission is replaced when the next street starts); enemies/boss live in `Section` and are rebuilt from JSON on every `enter()` — except **kills**, which are persisted in `State` (`defeatedEnemies`, `<street>/<id>#<slot>` → where the body lies) and reappear as corpses on re-entry. The **slot** is the entity's place in the section's list: two enemies that share an id (e.g. two `lysy-blokers`) keep their own body.
- **Street JSON schema** (`data/streets/01-narutowicza.json`) — one file per street, the file name is the street id used by every asset convention:
  - `name` — the display name of the street (e.g. "Narutowicza").
  - `mission: [log, ...]` — **the mission of the street**: one log line per stage, the index is the stage (0 = the start, entered automatically with the street). The HUD shows `mission[0]` on the first log row and `mission[stage]` on the second one (once the mission moved on). The stage moves on through the **transition maps** `{ "0": 1 }` ("while the mission is on stage 0, move it to stage 1") found in the section and interaction triggers.
  - `sections: [ ... ]` — the sections of the street, **from left to right**; the player walks into the neighbouring section and may come back. There is no `route`, no `exitLeft`/`exitRight` and no `boundaries` — the ends of the street are walled by convention (the first section has a left wall, the last one a right wall).
  - A section: `name`, optional `trigger: { on: "enter", mission: { "1": 2 } }` (what happens when the player enters — here: the mission moves on), optional `highlight: [ { x, y, position: [x1, x2], mission: [stages] } ]` (background overlays — the image is `assets/bg/<street>-<section>-<highlight>.png`; an overlay is shown when the player stands in its `position` range and/or the mission is on one of its `mission` stages), optional `interactions`, `enemies`, `boss`.
  - An interaction: `id`, `type: "walkable"`, `x1`/`x2` (the stretch of the section where the interaction may happen), `trigger: [ { on: "enter", stay: 3000, mission: { "0": 1 }, give: "beer", cost: 1 }, ... ]` — one behaviour per mission stage: the first entry whose `mission` map starts at the current stage wins, an entry **without** a `mission` map is the fallback for every other stage. `stay` is how long the player disappears in the spot. The **exchange** — the `mission` map (if any), the item of `give` and the price of `cost` — happens **200 ms before the player leaves the spot**, so the HUD (the objective and the money ↔ item swap) changes while he is still inside. The sound of the interaction is `assets/sounds/<street>-<interaction>-<trigger number>.mp3` and it plays **when the player disappears in the spot**, not when the walk-in starts.
  - An enemy: `id`, `type` (a `data/characters/<type>.json`), `trigger` (`always` | `distance` | `hit`), optional `distance` (for the `distance` trigger), `x`, `y`. `hit` = peaceful until the player hits him, `distance` = peaceful while the player is farther away than `distance`, `always` = fighting from the start. A dead enemy keeps lying where he fell.
  - A boss: `id`, `type`, `mission: [stages]` (the stages he exists on), `trigger` (same values as for the enemies), `x`, `y`.
- **Enemy types** are defined by `data/characters/<type>.json` (stats + move set). Types without a config file (`rat`, `thug`) are silently skipped at spawn — street JSON may reference them ahead of implementation.
- Coordinates: actor `x`/`y` are the **frame top-left** in world px; the section bg is drawn stretched to the full 1600x800 canvas.
- Errors and code comments are English; user-facing strings and error `throw`s are Polish.

## Content pipeline (goal)

Ultimately the game must be **configurable via files**: sections, enemies, NPCs and missions are defined in configuration files, and assets are selected based on **naming conventions**. The architecture must make expansion easy — adding more sections and streets later is expected to be routine.

- **New section** = background photo + a section entry in the street JSON + characters + mission transitions + audio = new section (pure file work, no code changes).
- **New street** = a new file `data/streets/<number>-<name>.json` (+ its assets). The game finds the streets by name and plays them one after another — no code change, no registration.

## Controls

Desktop keyboard; the move and `jumpKey` mappings live in the character config. Current defaults:

- ← / →: walk (keeps walking in place when blocked); Space: punch (stands still while attacking, alternating hands); ↑: jump (walk cycle plays in the air; **holding ↑ keeps hopping**; plays `player-jump.mp3`; side arrows stay live mid-jump) — **except** at a walkable spot, where ↑ enters the interaction instead (Rudy walks in, disappears for the trigger's `stay` and walks back out; the overlay stays visible through the whole sequence).
- **Debug**: holding **Shift** (either one) moves Rudy **4× faster** while walking — including the mid-jump drift (`DEBUG_SPEED_MULTIPLIER` in `src/actors/player.js`).
- ↓: **does nothing** — the backward step (the "retreat"/moonwalk) was removed by the owner on 2026-10-19; the jump is the only evasion. The key is still swallowed so the page does not scroll.
